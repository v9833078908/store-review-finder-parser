Практичное разделение “проще/поумнее”:
1. Проще, массово, дешево: classify_batch -> openai/gpt-5-mini или deepseek/deepseek-chat-v3.1.
2. Средняя сложность: analyze_batch -> openai/gpt-5-mini или google/gemini-2.5-flash.
3. Сложная синтезация/приоритизация: unified_report -> openai/gpt-5 / anthropic/claude-sonnet-4.5 / google/gemini-2.5-pro.
4. Эскалация на “умную” модель только по триггерам: low confidence, конфликт категорий, критические subcategory (crash, login_auth, progression_loss).

Что важно при переходе на OpenRouter
1. Сразу начать писать usage-метрики на каждый вызов (prompt/completion/cached/cache_write/cost) через встроенный usage объект.
2. Использовать provider routing:
- sort (по цене/latency/throughput),
- max_price,
- allow_fallbacks,
- only/ignore для контроля провайдеров.
3. Prompt caching в вашем кейсе не главный источник экономии: общий статический префикс батч-промптов сравнительно короткий; сначала выгоднее minify JSON + compact schema.
