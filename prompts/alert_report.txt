# Output Format

Generate a markdown report with the following structure:

```markdown

## Executive Summary

[2-3 sentences summarizing the alert situation. Be specific about what changed and severity.]

[For known issues that showed spike vs baseline:]

### [Issue Name] ([N] reports, baseline: [M]/day)

[If >= 5 feature requests in same subcategory:]
- **Top request category:** [subcategory] ([N] mentions)

2. **Short-term:** [Follow-up investigations/fixes]
```

# Guidelines

- **Be specific:** Use actual numbers from the data
- **Be actionable:** Every recommendation should have a clear next step
- **Consider changelog:** Link issues to recent changes when possible
- **Device clustering:** If multiple reports mention same device, highlight compatibility concerns
- **Severity assessment:**
  - Critical: Crashes, data loss, payment issues (>5 reports)
  - High: Major functionality broken (3-5 reports)
  - Medium: UX degradation, performance issues (3-5 reports)
  - Low: Minor bugs, cosmetic issues
- **Language:** Write in English regardless of review language
- **Length:** Keep under 400 words total

# Alert Threshold Logic

**Alert triggered if ANY of:**
- new_bug count > 2x baseline (spike detection)
- >= 3 crash reports in 48h post-update
- >= 5 new_bug reports in same subcategory
- Critical subcategories (crash, progression_loss, login_auth) have any new reports

**Baseline:** Average daily new_bug count from previous version period (7+ days)
